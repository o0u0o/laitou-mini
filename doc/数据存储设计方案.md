# 数据存储设计方案

> 版本：v1.0 | 日期：2026-05-09 | 作者：来头小程序团队

## 1. 背景

当前阶段后端 API 尚未就绪，但前端页面开发和产品验证需要持续推进。需要一套低成本的本地数据方案，同时不影响后续无缝切换到远程 API。

## 2. 方案选型

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **JSON 文件** | 小程序原生 `require()` 支持；与 API 返回格式完全一致，迁移成本为零；git diff 友好 | 数据量大时包体积增大 | **采用** |
| CSV 文件 | Excel 编辑友好 | 小程序无内置解析器，需引三方库；全是字符串，需手动转类型；与 API 格式不一致 | 不采用 |
| wx.setStorage | 原生 KV 存储 | 不适合结构化列表查询；数据不进版本控制；用户清缓存即丢失 | 不采用 |
| 云开发数据库 | 免服务器 | 有额外成本；依赖微信云环境；数据结构受限 | 可选（后期） |

## 3. 目录结构

```
laitou-mini/
├── data/                          ← 本地数据源（JSON 文件）
│   ├── banners.json               ← 轮播图数据
│   ├── companies.json             ← 公司/机构列表
│   └── categories.json            ← 类型分类枚举
│
├── model/                         ← 数据访问层（Model）
│   ├── datasource.js              ← 数据源适配器（核心）
│   ├── banner.js                  ← 轮播图 Model
│   └── company.js                 ← 公司 Model
│
├── config/
│   └── config.js                  ← 全局配置（含 useLocalData 开关）
│
├── utils/
│   └── http.js                    ← 网络请求工具（API 模式使用）
```

## 4. 核心架构：数据源适配器模式

### 4.1 数据流

```
┌──────────┐      ┌──────────────┐      ┌────────────────────┐
│  页面层    │ ──▶ │  Model 层     │ ──▶ │  DataSource 适配器  │
│ (home.js) │      │ (company.js) │      │                    │
└──────────┘      └──────────────┘      │  useLocalData?     │
                                         │  ┌───────────────┐ │
                                         │  │ true:          │ │
                                         │  │ require(JSON)  │ │
                                         │  ├───────────────┤ │
                                         │  │ false:         │ │
                                         │  │ Http.request() │ │
                                         │  └───────────────┘ │
                                         └────────────────────┘
```

### 4.2 设计原则

1. **页面层**只调用 Model 层，不关心数据来源
2. **Model 层**只调用 DataSource 适配器，不直接 require JSON 也不直接调 Http
3. **DataSource** 根据 `config.useLocalData` 分发到本地 JSON 或远程 API
4. 切换数据源**只改 config 开关一处**，页面和 Model 代码零改动

### 4.3 关键代码示例

**config/config.js**
```javascript
const config = {
  apiBaseUrl: 'https://laitou.aiuiot.com/laitou-java/app/',
  useLocalData: true  // true → 本地 JSON / false → 远程 API
}
```

**model/datasource.js**（简化示例）
```javascript
import { config } from '../config/config';
import { Http }   from '../utils/http';

const localCompanies = require('../data/companies.js'); // 注意：小程序构建器会自动追加 .js 后缀，本地数据需以 .js 模块形式导出

class DataSource {
  static async searchCompanies(keyword) {
    if (config.useLocalData) {
      // 本地过滤
      const filtered = localCompanies.companys.filter(c =>
        c.name.indexOf(keyword) > -1 || c.type.indexOf(keyword) > -1
      );
      return { companys: filtered.length ? filtered : localCompanies.companys };
    }
    // 走 API
    return await Http.request({
      url: '/app/company/list/like',
      data: { keyword }
    });
  }
}
```

**model/company.js**（调用方）
```javascript
import { DataSource } from './datasource';

class Company {
  static async searchByKeyword(keyword) {
    return await DataSource.searchCompanies(keyword);
  }
}
```

## 5. 数据格式约定

### 5.1 companies.json

```json
{
  "companys": [
    {
      "id": 101,
      "name": "示例科技（深圳）有限公司",
      "logo": "https://...",
      "province": "广东省",
      "city": "深圳市",
      "district": "南山区",
      "address": "科技园 XX 路 1 号",
      "source": "(2023)粤0305民初XXXX号",
      "type": "劳动争议"
    }
  ]
}
```

字段说明：
- `id`：唯一标识，后端就绪后由数据库自增生成
- `source`：信息来源/可核验依据
- `type`：分类，与 `categories.json` 对应

### 5.2 banners.json

```json
{
  "banners": [
    { "id": 1, "img": "https://..." }
  ]
}
```

### 5.3 categories.json

```json
[
  { "value": "劳动争议", "label": "劳动争议" },
  { "value": "行政处罚", "label": "行政处罚" }
]
```

## 6. 迁移路径

### 阶段一（当前）：纯本地

```
config.useLocalData = true
```

所有数据从 `/data/*.json` 读取，无后端依赖。

### 阶段二：逐接口迁移

后端就绪后，可按接口粒度逐步切换。在 `datasource.js` 中按方法级别控制：

```javascript
static async getBanners() {
  // 轮播已对接 API
  return await Http.request({ url: 'banner/list' });
}

static async searchCompanies(keyword) {
  // 公司列表还走本地
  if (config.useLocalData) { ... }
  return await Http.request({ ... });
}
```

### 阶段三：全量 API

```
config.useLocalData = false
```

一行改动完成切换。本地 JSON 文件可保留作为兜底/离线缓存。

## 7. 新增数据操作指南

### 添加公司/机构数据

1. 打开 `data/companies.json`
2. 在 `companys` 数组中追加一条，`id` 取当前最大值 +1
3. 必填字段：`id`, `name`, `province`, `city`, `type`, `source`
4. 保存后刷新小程序即可看到

### 添加新数据实体

1. 在 `data/` 下新建 `xxx.json`
2. 在 `model/datasource.js` 中 require 并添加对应方法
3. 在 `model/` 下新建或复用已有 Model 调用 DataSource
4. 页面只调 Model，不直接引用 JSON

## 8. 注意事项

1. **包体积**：本地 JSON 会打入小程序包。数据量大时（>500 条）建议压缩或分片加载
2. **数据一致性**：本地 JSON 的字段结构必须与后端 API 返回格式保持一致
3. **敏感信息**：不要在 JSON 中存放真实个人信息、证据原件、联系方式
4. **版本控制**：`data/*.json` 纳入 git 管理，每次数据变更都有记录
